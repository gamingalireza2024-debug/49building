## معرفی پروژه

«ساختمان ۴۹» یک سیستم مدیریت ساختمان مسکونی است که برای مدیریت شارژ ماهانه، شارژ عمرانی، پرداخت‌ها، هزینه‌ها، بدهی‌های قبلی، پروژه‌های عمرانی، و ارتباطات ساکنین طراحی شده است.

### مشخصات ساختمان

- **۳۶ واحد مسکونی** در ۵ طبقه
- طبقات ۱ تا ۳ و ۵: هر کدام ۸ واحد (۱۰۱ تا ۱۰۸، ۲۰۱ تا ۲۰۸، ۳۰۱ تا ۳۰۸، ۵۰۱ تا ۵۰۸)
- طبقه ۴: ۴ واحد (۴۰۱ تا ۴۰۴)
- دو صندوق مالی مستقل: **شارژ ماهانه** و **شارژ عمرانی**

---

## ویژگی‌ها

### مدیریت مالی

- **دو صندوق مستقل**: شارژ ماهانه و شارژ عمرانی کاملاً جدا نگهداری می‌شوند — تهاتر بین صندوق‌ها ممنوع است.
- **بدهی‌های قبلی**: ثبت مانده ابتدای دوره هر واحد با تفکیک ماهانه/عمرانی و اعتبار (طلب) تفکیک‌شده.
- **صدور شارژ**: شارژ مساوی یا متراژی برای همه یا بخشی از واحدها، با جلوگیری از صدور تکراری.
- **ثبت پرداخت**: با تخصیص اختیاری به پروژه‌ی عمرانی و اعتبارسنجی مبلغ مثبت.
- **ثبت هزینه**: با دسته‌بندی، صندوق (ماهانه/عمرانی)، فایل رسید، و شماره مرجع.
- **گزارش پروژه‌های عمرانی**: بودجه مصوب، شارژ صادرشده، وصول‌شده، باقی‌مانده، هزینه، و مانده نقدی.
- **گردش حساب واحد**: نمایش تراکنش‌های هر واحد با مانده دو صندوق به‌صورت مستقل.
- **موجودی افتتاحیه‌ی صندوق**: ثبت موجودی اولیه با اعتبارسنجی عدد صحیح نامنفی.

### مدیریت ساختمان

- **واحدها، مالکین، مستاجرین**: ثبت و ویرایش اتمیک (در یک تراکنش) با audit خودکار.
- **اعلانات**: انتشار اعلان برای ساکنین.
- **درخواست تعمیرات**: ثبت توسط ساکنین، پیگیری توسط مدیر.
- **نظرسنجی**: ایجاد نظرسنجی با گزینه‌های متعدد و رأی‌گیری.
- **اسناد**: آپلود و دسته‌بندی اسناد ساختمان.
- **پیام‌ها**: ارسال پیام ساکن به مدیر.

### امنیت و حسابرسی

- **سابقه‌ی کامل تغییرات (Audit Log)**: هر درج/ویرایش/حذف مالی با actor، reason، و change_data ثبت می‌شود.
- **جلوگیری از ارتقای نقش**: trigger روی `profiles` که فقط مدیر می‌تواند نقش را تغییر دهد (با escape hatch برای bootstrap اولین مدیر).
- **Bootstrap اولین مدیر**: تابع `claim_first_admin` که فقط زمانی که هیچ مدیری وجود ندارد کار می‌کند.
- **RLS کامل**: همه‌ی جداول Row Level Security دارند — اعضا فقط می‌خوانند، فقط مدیر می‌نویسد.
- **Storage خصوصی**: bucket رسیدها خصوصی است و فقط کاربران واردشده دسترسی دارند.

### اصول طراحی

1. **منطق حسابداری در `b49_accounting.js`**: توابع خالص قابل تست — تست‌ها توابع واقعی برنامه را می‌آزمایند، نه کپی جداگانه.
2. **عملیات اتمیک در RPC**: درج/ویرایش + audit در یک تراکنش Postgres — اگر audit شکست بخورد، عمل rollback می‌شود.
3. **Security Definer با search_path صریح**: همه‌ی RPCها `set search_path = public` دارند تا در برابر search path hijacking ایمن باشند.
4. **Idempotent migrations**: همه‌ی migrationها با `create or replace` / `drop if exists` / `add column if not exists` نوشته شده‌اند — اجرای مجدد خطا نمی‌دهد.

| تابع | عمل |

## امنیت

### Row Level Security

- **خواندن**: همه‌ی کاربران واردشده می‌توانند داده‌ها را بخوانند (شفافیت مالی).
- **نوشتن**: فقط مدیر (admin) می‌تواند داده‌ی مالی ثبت/ویرایش/حذف کند.
- **استثناها**: ساکنین می‌توانند پیام بفرستند، درخواست تعمیرات ثبت کنند، و در نظرسنجی رأی دهند.

### Guard Profile Role

Trigger روی جدول `profiles` که:
- جلوی ارتقای نقش توسط کاربر غیرادمین را می‌گیرد.
- **Escape hatch**: اگر هنوز هیچ مدیری وجود نداشت، اجازه‌ی ایجاد/ارتقا می‌دهد (برای bootstrap).
- بعد از اولین مدیر، فقط مدیر یا SQL Editor می‌تواند نقش را تغییر دهد.

### Audit Log

هر تغییر مالی (پرداخت، هزینه، واحد) در همان تراکنش با:
- `actor`: کاربری که عمل را انجام داده (`auth.uid()`)
- `action`: insert/update/delete
- `reason`: دلیل عمل
- `change_data`: داده‌ی تغییرات (JSONB)

## نصب و راه‌اندازی

### پیش‌نیازها

- یک پروژه‌ی Supabase (پلن رایگان کافی است)
- Node.js 20+ (برای اجرای تست)

### مراحل

۱. **کلون ریپو:**
```bash
git clone https://github.com/gamingalireza2024-debug/49building.git
cd 49building
```

۲. **ایجاد اسکیمای دیتابیس:**

در Supabase Dashboard → SQL Editor → New query، فایل‌ها را به‌ترتیب اجرا کنید:

```
۱. schema.sql          (اسکیمای پایه + RLS + seed)
۲. migration_v2.sql    (حسابداری: prior_debts, projects, audit_log)
۳. migration_v3.sql    (امنیت + RPC + bootstrap مدیر)
```

۳. **پیکربندی Auth:**

در Supabase Dashboard → Authentication → Settings:
- URLهای مجاز را تنظیم کنید
- Email auth را فعال کنید

۴. **Bootstrap اولین مدیر:**

بعد از ثبت‌نام اولین کاربر، در SQL Editor:
```sql
select public.claim_first_admin();
```

۵. **اجرای تست (اختیاری):**
```bash
node tests/unit/accounting.test.js
```

## تست و CI

### تست‌های حسابداری

فایل `tests/unit/accounting.test.js` شامل ۳۵ سناریو است که توابع واقعی `b49_accounting.js` را می‌آزماید:

- توزیع شارژ مساوی و متراژی
- تخصیص پرداخت به پروژه
- rollback در صورت شکست audit
- مقادیر بزرگ و صفر بدون NaN

| **e2e** | تست مرورگر Playwright | غیرفعال (TODO) |
